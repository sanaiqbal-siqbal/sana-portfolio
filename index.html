The problem

Finding good B2B leads in Pakistan means searching scattered sources by hand. The data is messy and often outdated, and many tools fill the gaps with guesses.

What I built

A research pipeline that collects public company data, normalizes it, and tracks where every field came from. A scoring layer rates niches with explicit rules, and a ChromaDB index lets the chat retrieve evidence before it answers.

How it works

  1. Collect from Google Places, search engines, directories, associations, and company websites.
  2. Normalize companies and niches into structured records with source and confidence.
  3. Score niches and companies using evidence-based rules.
  4. Store the records and rebuild the vector index.
  5. Serve the dashboard, exports, and cited chat through FastAPI.

Key decision: no invented data

The system never fabricates emails or funding figures. Unverified data is flagged, so the output stays usable for real outreach.

Stack

Python, FastAPI, SQLAlchemy, PostgreSQL/SQLite, ChromaDB, Groq, React 18, Vite, Tailwind CSS, Recharts. Deployed on Render (API) and Vercel (frontend).

The problem

Sales work jumps between research, CRM updates, and follow-ups. One chatbot with one giant prompt gets noisy, slow, and expensive.

What I built

A command goes to Soraq Core, then to an agent orchestrator, then to the right specialized agent. A Mission Control view shows what the agents are doing, and a knowledge graph and memory feed context back in.

Engineering story: fixing voice

Browser voice input kept crashing the page. I tested the likely causes one at a time: the Speech API, heavy UI animation, and audio capture. I removed the animation loops and replaced browser speech recognition with MediaRecorder plus server-side Whisper through Groq. Voice capture became crash-safe, and failures now have a clear owner.

Key decision: route, don’t stuff

Specialized agents keep each prompt focused, which cuts noise and cost and makes behavior easier to debug.

Stack

Groq (chat and Whisper), Supabase (auth, workspaces, row-level security, server functions), multi-agent orchestration.

The problem

Most job seekers get vague resume advice and little interview practice. Generic chatbots give generic answers, and slow replies make practice feel fake.

What I built

A full product with sign-in, resume upload, structured analysis, a career path, and mock interviews. PDFs become structured career signals: skills, experience, and gaps.

Key decision: latency is a feature

I chose Groq because a slow interviewer breaks trust. AI calls run in Supabase Edge Functions so keys stay on the server, and row-level security keeps each user’s data private.

Stack

React, Vite, Tailwind CSS, Supabase (Auth, Storage, RLS, Edge Functions), Groq API, Vercel.
